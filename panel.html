Control panel

Review a change before anything is written

Prepare a proposal in this browser, look up a known fix, or ask the server to dry-run the allowlisted fixer. The preview button always sends mode dry-run.

1 Proposed code

Prepare proposal packages the code, the target file, and the intent, then shows that JSON in Result. The package stays in this browser.

2 Where this would be inserted

Name the file and say why the code belongs there. The server inserts only at a marked zone in an allowlisted file, and only when a request uses mode apply.

3 Dry-run the allowlisted fix

Run dry-run sends the target file, fixer replace_single_with_maybeSingle, and mode dry-run to POST /apply-fix. It leaves the proposed code above out of that request, and it leaves the file as it is. The request also leaves out the x-panel-token header, so Result shows whether PANEL_TOKEN is set.

What this server expects

Set these in the environment of the process that runs node index.js. Keep the values out of the repository. This page has nowhere to type them.

Supabase

SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY back learning events, known fixes, this feed, proposals, and patch history. Copy the project URL and the service role key from the project’s API settings.

OpenAI

OPENAI_API_KEY is read by POST /panel/analyze-test. The buttons on this page leave that route alone. Calling it with Authorization: Bearer and your panel token reports a missing key.

Panel token

PANEL_TOKEN is the secret for protected routes. POST /apply-fix and POST /apply-proposal expect header x-panel-token. POST /panel/ping and POST /panel/analyze-test expect Authorization: Bearer.

Look up a known fix

Suggest fix sends the tool and message to POST /suggest-action. The server hashes that pair and looks for a row in verified_solutions.
